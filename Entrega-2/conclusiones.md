# Conclusiones

A continuación, se presentan las conclusiones del trabajo realizado. En primer lugar, el uso de herramientas para llevar a producción el entrenamiento del modelo predictivo diseñado en la entrega anterior facilita su uso en contextos realistas, similares a la industria. El uso de Airflow permite mantener el modelo a lo largo del tiempo, facilitando su reentrenamiento según las necesidades que generan la incorporación de datos nuevos semana a semana. Esto se evidencia aún más al momento de detectar drift, dado que representa la necesidad de adaptar el modelo a las observaciones más recientes.

Por otro lado, el uso de Gradio y FastAPI para implementar una interfaz web y backend que permitan disponibilizar el modelo a través de un endpoint aportan aún más valor a la existencia del modelo, ya que facilita su acceso y uso por parte de los usuarios sin la necesidad de que estos intervengan en el pipeline de entrenamiento. Dentro de los desafíos detectados en este proceso, se destaca la necesidad de un diseño apropiado de la interfaz gráfica desarrollada en Gradio, pues al ser varias variables de distintos tipos de datos, dificulta el proceso de creación de una interfaz amigable para que el usuario pueda ingresar datos y generar nuevas predicciones. Gracias al uso de componentes como dropdowns, se facilita mucho el uso correcto del modelo, y previene posibles errores, por ejemplo, al entregar un `json` mal formateado o con datos incorrectos.

Finalmente, una versión futura del flujo se beneficiaría de las siguientes mejoras:
1. El dataset `historic.parquet` puede crecer a dimensiones dificiles de manejar a través del tiempo, luego, se beneficiaría de abandonar las semanas más antiguas a medida que se incorporan las más recientes.
2. Más aún, el uso de un archivo como `historic.parquet` para mantener la data histórica puede derivar en consecuencias negativas, por ejemplo, si más de una ejecución intenta actualizarlo al mismo tiempo. Así, una solución más segura es el uso de un sistema de gestión de bases de datos relacional para preservar esta información en el tiempo.
3. La detección de drift puede mejorar al comparar otros aspectos de los datos que no se reflejen en la comparación de métricas como `f1-score`, tales como comparar las distribuciones con tests de hipotesis u el uso de métricas obtenidas de estadística descriptiva.
